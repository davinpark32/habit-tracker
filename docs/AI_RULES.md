# Hopit AI RULES v1
ChatGPT · Cursor 공통 개발 규칙
기준일: 2026-08-19

## 문서 목적
이 문서는 Hopit을 ChatGPT와 Cursor로 공동 개발할 때 두 AI가 따라야 할 공통 행동 규칙이다.
AI는 코드를 작성하거나 수정하기 전에 PROJECT 문서와 이 문서를 확인한다.

## 1. 최우선 원칙
- Hopit은 현재 2인 테스트용 프로토타입이다.
- 요청받지 않은 서비스용 기능이나 과도한 구조를 추가하지 않는다.
- 기능 구현보다 기획 의도를 우선한다.
- 특히 '목표 달성 → 보상 → 직접 펫과 상호작용 → 성장'이라는 핵심 경험을 임의로 단순화하지 않는다.
- 사용자가 프로그래밍에 익숙하지 않다는 전제로 중요한 기술 선택이나 위험은 쉬운 말로 설명한다.

## 2. 작업 시작 전
- 먼저 현재 프로젝트의 파일과 기존 구현을 확인한다.
- 기존 구현을 보지 않고 동일 기능을 새로 만들지 않는다.
- 이번 작업의 담당 범위를 확인한다.
- 요청받지 않은 다른 기능은 가능한 한 수정하지 않는다.
- 작업이 다른 담당자의 기능, 공용 데이터, 파일 구조에 영향을 줄 가능성이 크면 구현 전에 그 사실을 알린다.

## 3. 코드 수정 원칙
- 잘 동작하는 기존 기능을 이유 없이 재작성하지 않는다.
- 한 번의 요청에서 가능한 한 하나의 기능 또는 명확한 작업 범위에 집중한다.
- 대규모 리팩터링, 폴더 구조 전면 변경, 프레임워크 교체는 사용자가 명시적으로 요청하지 않는 한 하지 않는다.
- 새 라이브러리나 외부 서비스를 추가하기 전에 왜 필요한지 설명한다.
- 기존 기술로 간단히 해결 가능하면 새 의존성을 추가하지 않는다.
- 임시로 에러를 숨기는 방식보다 원인을 찾아 수정한다.
- 단, 프로토타입 단계에 맞게 과도한 설계는 피한다.

## 4. 공동개발 / 충돌 방지
- 같은 기능을 두 사람이 동시에 개발하지 않는 것을 기본 원칙으로 한다.
- 다른 담당자가 만든 영역을 수정해야 할 경우 변경 범위를 최소화한다.
- 공용으로 사용되는 데이터 구조나 핵심 인터페이스를 임의로 변경하지 않는다.
- 변경이 필요하면 무엇이 바뀌고 다른 기능에 어떤 영향이 있는지 먼저 설명한다.
- 머지하기 쉽도록 작업과 무관한 파일의 포맷팅, 이름 변경, 위치 이동 등을 하지 않는다.
- 작업 완료 시 변경한 파일과 주요 변경 내용을 짧게 정리한다.

## 5. UI / 스마트폰 규칙
- 모든 주요 화면과 조작은 스마트폰을 우선 기준으로 설계한다.
- 터치 조작을 우선한다.
- Long Press 등 기획에 지정된 입력 방식을 임의로 클릭 방식으로 대체하지 않는다.
- 초기 UI는 AI가 임시로 제작할 수 있지만 이후 실제 에셋으로 교체하기 쉬운 구조를 유지한다.
- UI를 개선한다는 이유로 기획에 없는 화면, 메뉴, 버튼, 기능을 임의로 추가하지 않는다.
- 기능이 같다면 화려함보다 알아보기 쉬움과 조작 피드백을 우선한다.

## 6. 에셋 및 3D 캐릭터
- 임시 이미지, 아이콘, 캐릭터 표현은 나중에 친구가 만든 에셋으로 교체될 수 있다는 전제로 구현한다.
- 특정 임시 에셋에 기능 로직이 강하게 종속되지 않도록 한다.
- 3D 캐릭터 관련 기술이나 파일 형식이 아직 확정되지 않았다면 임의로 복잡한 3D 시스템을 도입하지 않는다.
- 목업 사양이 정해진 뒤 3D 기술을 결정한다.

## 7. 데이터와 저장
- 현재는 개발자 2명 테스트용 프로토타입이므로 실제 서비스 규모의 백엔드를 임의로 도입하지 않는다.
- 목표, 완료 상태, 보상 보유량, 펫 성장 등 서로 연결되는 데이터의 이름과 의미를 일관되게 유지한다.
- 기존 저장 데이터와 호환되지 않는 변경이 필요하면 구현 전에 사용자에게 알린다.

## 8. 불명확한 기획 처리
- 기획서에 없는 세부사항이 구현상 사소하고 쉽게 되돌릴 수 있다면 가장 단순한 방법을 선택할 수 있다.
- 사용자 경험, 데이터 구조, 다른 담당자의 작업, 향후 에셋 교체에 큰 영향을 주는 사항은 AI가 임의로 결정하지 말고 질문한다.
- 기획서와 최신 사용자 지시가 충돌하면 최신 사용자 지시를 우선한다.

## 9. 작업 완료 시 보고
작업이 끝나면 다음 세 가지를 쉬운 말로 알려준다.
1. 무엇을 바꿨는지
2. 사용자가 무엇을 직접 확인하면 되는지
3. 아직 남은 문제나 주의점이 있는지

가능하면 실제 스마트폰 크기 또는 모바일 브라우저 환경에서 핵심 동작을 확인할 수 있도록 안내한다.
완료되지 않았거나 확인하지 못한 부분을 완료했다고 말하지 않는다.

## 10. 현재 역할 참고
### 친구 + Cursor
- 캐릭터 3D 목업
- UI 관련 피드백 및 구현

### 사용자 + ChatGPT
- 파를레 기능 사양
- 목표 달성 UX
- 목표 설정 관련 전반

이 역할은 현재 2차 프로토타입 기준이며 이후 합의에 따라 변경될 수 있다.
